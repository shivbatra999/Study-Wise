### 6.6 Design principles applied

| Principle | Where it shows in our design | Evidence |
| :--- | :--- | :--- |
| Separation of concerns | Presentation (StudyUI), request routing (LocalApi), rules (services) and storage (LocalStore) are separate components in separate layers | 6.3, ADR-01 |
| Information hiding | RuntimeGateway hides the runtime's API and the model name; PassageIndex hides how passages are ranked and how vectors are stored; LocalStore hides the file layout | Generate, FindPassages, Persist interfaces; ADR-02, ADR-03 |
| Low coupling | Services ask PassageIndex a question ("most relevant passages for this question in this course") and receive only passages; changing ranking opens 0 other components | 6.3 coupling test |
| High cohesion | Every responsibility in 6.3 is one sentence about one subject; importing, answering and quizzing are separate components rather than one "AI service" | 6.3 table |
| Design for change | The most likely changes (runtime, model, retrieval method) each sit behind one component; a model change is a setting, not code | ADR-02, ADR-03, ADR-04 |
| Keep it simple (KISS) | One backend process, one database file, no separate vector database, no message bus; relaxed layering instead of pass-through components | ADR-01, ADR-03 |
