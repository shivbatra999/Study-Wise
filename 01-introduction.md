# 1 Introduction

Owner: Lokesh Reddy Penugonda

## 1.1 Purpose of this document and of the system

This document is the P1 baseline of the Study-Wise software requirements specification. It is written for three readers: the CS 3354 instructor and teaching assistants who assess it, the team members who will design, build and test against it, and any student tester who needs to know what the system promises.

Study-Wise addresses a problem students have when they study for exams: their course material which consists of lecture slides, PDF notes and handouts is spread across many files, and the AI tools that could help them review it require uploading those files to a third-party cloud service, usually behind a subscription. That upload exposes instructors' material and the student's own questions to an outside company, and many students either cannot pay or do not want to. Study-Wise lets a student ask questions about their own course materials entirely on their own laptop, with every answer pointing back to the slide or page it came from.

## 1.2 Scope

| In scope — we will build this | Out of scope — we will not, and why |
| --- | --- |
| Importing text-based PDF and PowerPoint (.pptx) files into courses the student creates | Scanned or handwritten notes that need OCR — accuracy on scans is poor and OCR would consume roughly a third of the schedule |
| Answering a student's typed question from the materials of one selected course, with a citation to file and page or slide | Cloud sync or access from multiple devices — any server would break the privacy constraint CON-01 |
| Generating multiple-choice practice quizzes from selected materials, scoring them, and showing the source of each answer | Sharing materials or quizzes between students — redistributes instructors' content (stakeholder SH2) and needs user accounts |
| Keeping courses and imported materials on the device between sessions; removing materials | Integration with UTD eLearning / Canvas — needs institutional API access and credentials the team does not control |

**Why the exclusions were excluded:** each exclusion either conflicts with a constraint or costs more schedule than its value to the core question we are testing. Any of them can be reconsidered through change control once the MUST requirements are met.

## 1.3 Definitions, acronyms and abbreviations

| Term or abbreviation | Meaning as used in this project |
| --- | --- |
| Course | To students, a course is a UTD class they are registered in. In Study-Wise, a course is a named collection of materials the student creates. This document always means the second; it is not linked to registration. |
| Quiz | In class, a quiz is graded work. In this document, a quiz is an ungraded set of practice questions generated by Study-Wise. Study-Wise never produces or submits graded work (see SH3). |
| Grounded answer | (a) An answer built only from the student's imported materials; (b) an answer that may also use the model's general knowledge. This document uses (a); the choice is unconfirmed — see Q1. |
| Material | A PDF or PPTX file the student has imported into a course. |
| Citation | The file name plus the page number (PDF) or slide number (PPTX) of a passage used in an answer or quiz question. |
| LLM | Large Language Model — a model that generates text from a prompt. |
| Local LLM runtime | Software already on the student's computer that runs an LLM and answers requests from other programs on the same machine (Ollama at P1; see A2). It is external to Study-Wise. |
| RAG | Retrieval-Augmented Generation — answering by first finding relevant passages in the student's materials and giving them to the LLM with the question. |
| Benchmark set | 20 questions with known answers, written by the team from two real lecture decks and stored in /docs/benchmark; used to verify QR-01 and QR-03. |
| Reference laptop | A team-owned laptop with 16 GB RAM, no discrete GPU, Windows 11 or macOS 14 or later, used for every performance measurement. Lokesh's laptop has 18 GB RAM. |
| MoSCoW | Priority scale: MUST, SHOULD, COULD, WON'T (for this release). |
| PDF / PPTX / OCR | Portable Document Format / PowerPoint Open XML presentation / Optical Character Recognition. |
